CLAUDE.md

Instructions Claude Code reads at the start of every session.

Claude Code loads this file automatically, so it's where the project's Git workflow is written down. It's guidance: Claude follows it, but nothing technically enforces it. The enforced rules live in .claude/settings.json.

Sections

  • Git workflow: check status and create a branch from main before starting work, using prefixes such as feature/, fix/, and docs/.
  • Committing: small, focused commits; review git diff --staged first; stage files by name; never commit secrets; don't skip hooks.
  • Pushing and sharing: never commit to main, ask before pushing, and never force-push.
  • Destructive and history-changing commands: commands that can lose work, which need an explicit request and a warning first.
  • Staying in sync: fetch before starting work, and stop on merge conflicts instead of guessing.
  • Working efficiently: prefer short, read-only commands and avoid interactive flags.

.claude/

Project-level configuration for Claude Code.

Settings in this folder are committed, so they apply to everyone who opens the repo in Claude Code. Personal overrides go in .claude/settings.local.json, which stays out of version control.

.claude/settings.json

Permission rules that enforce the most important Git safeguards.

Each rule matches a command Claude might run and puts it in one of three tiers. When rules overlap, deny wins over ask, and ask wins over allow.

Allow: runs without a prompt (24 rules)

Read-only commands such as status, diff, log, show, and fetch, plus switch -c, add, and commit. These are local and easy to undo.

Ask: always prompts you first (20 rules)

Commands that share work or change history: push, pull, merge, rebase, reset, restore, checkout, dropping stashes, deleting branches, commit --amend, and gh pr.

Deny: blocked (26 rules)

Force pushes, pushes to main, reset --hard, clean -f, filter-branch, --no-verify, changing global Git config, and reading .env*, *.pem, and bulky .git internals.

Rules match the start of a command, so a command with its flags in an unusual order can slip past a pattern. For real protection, also turn on branch protection for main on your Git host.

docs/index.html

This page.

A single self-contained HTML file with no dependencies. Open it directly in a browser, or publish it with GitHub Pages by serving from the /docs folder.

.gitignore

Files Git should never track.

Covers the usual clutter for Node, TypeScript, and Python projects, plus:

  • Secrets: .env, .env.* (except .env.example), and *.pem keys.
  • Build output and caches: node_modules/, dist/, build/, __pycache__/, and similar.
  • Machine-specific files: macOS metadata, editor settings, logs, and temp folders.

Together with the CLAUDE.md rule to stage files by name, this keeps secrets and generated files out of commits.

README.md

The front page of the repository.

Explains the three ways to use the repo and gives step-by-step instructions for each:

  • As a template: clone it, start fresh Git history, and build a new project on top.
  • As a reference: copy CLAUDE.md and merge the permission rules into an existing repository.
  • As a sandbox: practice Git operations with Claude Code using the suggested exercises.
